# Credentials & Access Needed for Public Deployment

This project is prepared for a public deployment (Render Static Site + Render Web Service + Supabase PostgreSQL, optional Gemini), but **no public HTTPS URL has been deployed or live-tested** from this environment. To complete deployment, you must provide/configure the following. **Do not paste secrets into chat; enter them only in Render/Supabase dashboards or your local `.env` files.**

## 1. Accounts / Access (required)
- **GitHub (or GitLab) account & repository access**: push this finalized project so Render can deploy from it.
- **Render account access**: to create/manage a Web Service (backend) and Static Site (frontend), set env vars, and deploy.
- **Supabase account & project access**: to create/use a PostgreSQL database and obtain the connection string.

## 2. Required Environment Values (secrets/config)

| Where | Variable | Required | What it is / where to get it |
|---|---|---:|---|
| Render **Backend Web Service** env | `DATABASE_URL` | **Yes (production)** | Supabase PostgreSQL connection string. Recommended SQLAlchemy form: `postgresql+psycopg2://USER:PASSWORD@HOST:PORT/DBNAME?sslmode=require` (app also normalizes `postgres://`/`postgresql://`). Get from Supabase Project Settings → Database/Connection string. |
| Render **Backend Web Service** env | `CORS_ORIGINS` | **Yes** | Exact deployed frontend origin(s), comma-separated, no trailing slash. Example: `https://<your-frontend>.onrender.com` (set/update after frontend URL is known). |
| Render **Frontend Static Site** env (build-time) | `VITE_API_BASE_URL` | **Yes** | Public backend API base URL: `https://<your-backend>.onrender.com/api/v1` (set/update after backend URL is known, then rebuild frontend). |
| Render **Backend Web Service** env | `GEMINI_API_KEY` | Optional | Google Gemini API key for live AI explanations (backend-only). If omitted/disabled, the app uses the built-in safe fallback explanation (no fabricated Gemini output). Get from Google AI Studio/API console under your account. |
| Local dev only (optional) | `frontend/.env` `VITE_API_BASE_URL` | Local use | `http://localhost:8000/api/v1` for local frontend dev. |
| Local dev only (optional) | `.env` values | Local use | Local SQLite `DATABASE_URL` works by default; fill Gemini/Supabase only if you want to test those locally. |

## 3. Values the Platform Provides / Auto-handles
- **`PORT`**: injected by Render for the backend web service (backend is configured to bind `0.0.0.0:$PORT`).
- **Public HTTPS URLs**: generated by Render after deployment (e.g. `https://<service>.onrender.com`). You must copy these into `VITE_API_BASE_URL` (frontend) and `CORS_ORIGINS` (backend) as above.

## 4. Recommended Render Configuration (already prepared)
- **Backend (Web Service):** root `.`, build `pip install --upgrade pip && pip install -r backend/requirements.txt`, start `uvicorn app.main:app --host 0.0.0.0 --port $PORT --app-dir backend`, health check `/health`. See `render.yaml`.
- **Frontend (Static Site):** root `frontend`, build `npm install && npm run build`, publish `dist`, SPA rewrite `/* -> /index.html` (see `frontend/public/_redirects`, `render.yaml`).
- **Database:** Supabase PostgreSQL via `DATABASE_URL`. Tables created on startup (best-effort) and Alembic migration included (`backend/alembic/versions/0001_create_analysis_records.py`).

## 5. Step-by-Step Actions to Complete Public Deployment
1. **Push** the finalized project folder to your GitHub/GitLab repository.
2. **Create Supabase project** (if needed) and copy the Postgres `DATABASE_URL` (keep secret).
3. **Deploy Backend on Render** (Blueprint `render.yaml` or manual): set `DATABASE_URL`, `CORS_ORIGINS` (temporary or update later), and optional `GEMINI_API_KEY`/`GEMINI_ENABLED`. Deploy and confirm `GET /health` and `GET /api/v1/health` are healthy at `https://<backend>.onrender.com`.
4. **Deploy Frontend on Render**: set `VITE_API_BASE_URL=https://<backend>.onrender.com/api/v1` and build/deploy. Note the frontend public URL.
5. **Finalize CORS**: set backend `CORS_ORIGINS=https://<frontend>.onrender.com` and redeploy/restart backend if needed.
6. **Live verification (required before claiming complete):** open the frontend public HTTPS URL in a browser and verify end-to-end: symptom analysis (valid case), duration-only rejection (no prediction), results sections (possible unconfirmed conditions, NLP/ML/RAG/AI separation, sources, follow-ups, safe next steps, urgency/emergency guidance, disclaimer), history with Supabase, Gemini live response or safe fallback, and no CORS/browser errors.

## 6. Security Notes
- Keep `GEMINI_API_KEY` and `DATABASE_URL` **server-side only** (Render backend env vars). Never place them in frontend code or `VITE_*` variables.
- `.env` files with real secrets must not be committed. Repo `.gitignore` excludes `.env` and `.env.*` (except examples). Local `.env` files in this workspace are placeholders/examples only.
- I cannot invent credentials or claim a live public URL until you deploy and verify it.
